# 05 — Detalle real de la waveform por ventana

## 2026-08-24 · implementación base terminada; medición visual pendiente

### Lectura nativa acotada

Se añadió `SourceManager::source_peaks_window(source_id, start_frame,
end_frame, bucket_count)`. La lectura empieza con `sf_seek` (o `seekg` sin
libsndfile), termina al final de la ventana y nunca publica un resultado
parcial mientras el source está en `streaming`.

La prueba nativa cubre fuentes en memoria y respaldadas por PCM16. Para una
ventana alineada compara además cada extremo **bit a bit** con el recorte de
`source_peaks` a la misma resolución.

### Transporte binario y compatibilidad

La API nueva es aditiva. `lt_audio_engine_get_source_peaks`, los DTO del
`SongView`, el formato `.ltpeaks` v6 y sus LOD siguen intactos. La nueva ABI
devuelve una vista prestada con planos `float32` contiguos; Rust los copia y
decodifica como little-endian antes de otra llamada nativa.

Tauri expone `get_waveform_window` como comando asíncrono sobre un worker. No
toma `DesktopState::session`; sólo accede brevemente al controlador de audio.
Si el source no existe o sigue preparándose devuelve `null`, que no es un error
visible ni fuerza una decodificación del archivo.

### Mejora progresiva en el tile

Por debajo del techo del LOD persistido (`sampleRate / 256`, 187,5 px/s a
48 kHz) no cambia nada. Por encima, cada tile visible pide tantos buckets como
píxeles físicos va a rasterizar:

1. El LOD grueso se pinta y permanece visible.
2. La ventana fina llega fuera del frame.
3. El mismo tile encola su sustituto fino y sólo cambia de canvas cuando la
   rasterización ha terminado.

Las respuestas pertenecientes a un zoom/viewport abandonado se descartan. Los
datos finos y sus superficies comparten el techo existente de 48 MiB; no hay
una segunda caché ilimitada. Un fallo o source no disponible conserva el LOD
grueso como fallback.
